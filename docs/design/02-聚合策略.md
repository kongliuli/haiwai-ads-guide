# 善用聚合（Mediation）打破单一平台瓶颈

> 编写模型: Composer (Cursor Agent) · 2026-10-15

## 何时上聚合

当你的应用日活（DAU）突破一定量级（如**海外 DAU 大于 1000**）后，不要只接一家 SDK。

单一广告网络的填充率与出价会随地区、时段、广告位波动；通过聚合让多家广告源对同一展示机会实时竞价，通常能拉高有效 eCPM 与整体收益。

## 推荐主聚合层

任选其一作为「主聚合层」（不要两套主聚合并存，避免双 SDK 竞态与包体膨胀）：

| 主聚合层 | 适合谁 | 备注 |
|----------|--------|------|
| **AdMob Mediation** | 已用 AdMob、偏工具/内容 App | 个人出海最常见路径；与 Google 账号体系一体 |
| **AppLovin MAX** | 游戏、强依赖激励视频/插屏 | Bidding 与 eCPM 表现强势 |
| **Unity LevelPlay** | Unity 项目、游戏向 | 与引擎集成顺滑；含 Unity Ads 网络 |

## 建议配置的广告源（Bidding）

在主聚合层内同时配置多家广告源做实时竞价（Bidding），常见组合：

- Meta Audience Network  
- Unity Ads  
- Pangle（穿山甲海外版）  
- Mintegral  
- （以及主聚合层自有网络，如 AdMob / AppLovin / ironSource Ads）

具体 adapter 以各聚合平台后台「Mediated networks」列表为准；版本需与主 SDK 兼容。

## 预期收益

配置合理时，通常可将整体 **eCPM 和收益拉升约 20%–50%**（相对单网络）。实际幅度取决于：

- 用户地区结构（Tier-1 vs Tier-3）
- 广告位类型（激励视频 / 插屏通常提升更明显）
- 是否真正走 Bidding（而非仅 waterfall）
- 各源账号是否合规、是否过审

## 实施注意（个人开发者）

1. **先稳定单一网络**，再开 Mediation；避免 Day-1 就堆满 adapter。  
2. **Meta AN 现多要求经 Bidding 聚合接入**，不要指望长期单独直连。  
3. 维护 **app-ads.txt**（应用）或 **ads.txt**（网站），否则部分源会限流或拒投。  
4. 隐私：ATT（iOS）、UMP/同意弹窗（EEA）、各平台数据政策需一并落地。  
5. 包体与初始化耗时：每多一个 adapter 都有成本，按收益贡献裁剪。
