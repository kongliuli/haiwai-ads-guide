# 广告位元数据（PlacementSpec）

> 编写模型: Composer (Cursor Agent) · 2026-10-15

各 SDK 在分发、呈现、Bridge 上形态不同，但对「逻辑广告位」的描述可以归一。本文定义跨 AdMob / AdSense / AppLovin MAX / Unity Ads / LevelPlay / Meta AN 可用的 **PlacementSpec**，以及格式与生命周期事件对照表。（仓库不再收录 SDK 二进制，仅保留文档站。）

相关：[01-主流平台总览](./01-主流平台总览.md) · [02-聚合策略](./02-聚合策略.md) · [中文文档站](../../site/README.md)

---

## 1. 为何需要逻辑广告位

各平台真实坐标互不兼容（Ad Unit ID、Placement Name、`ca-pub`+slot 等）。若以某一家 ID 当全局主键，换聚合或加广告源时台账会碎。

**PlacementSpec.id** 是产品侧稳定主键；各网账号里的 unit 只进 `bindings[]`。

## 2. PlacementSpec 结构

```text
PlacementSpec
├─ identity          # 内部 id / 显示名 / 场景说明
├─ format            # 归一格式枚举
├─ surface           # 容器与渲染方式
├─ auction           # 要量方式
├─ creative          # 创意与协议约束
├─ lifecycle         # 期望事件契约
├─ privacy           # 合规约束（可后置细化）
├─ bindings[]        # 映射到各平台真实 ad unit
└─ ops               # 频次、超时、缓存等
```

### 2.1 identity

| 字段 | 说明 |
|------|------|
| `id` | 内部主键，如 `home_rv_1` |
| `name` | 展示名 |
| `scene` | 业务场景简述（首页激励、结算插屏等） |

### 2.2 format（归一枚举）

| 值 | 含义 |
|----|------|
| `banner` | 横幅（尺寸见 `size`） |
| `mrec` | 中矩形（约 300×250） |
| `interstitial` | 插屏 |
| `rewarded` | 激励视频/激励广告 |
| `rewarded_interstitial` | 激励插屏（非家家支持） |
| `app_open` | 开屏 |
| `native` | 原生信息流（含 native banner） |
| `web_slot` | Web 位（AdSense） |

尺寸与 format 解耦：

```text
size?: { w?: number, h?: number, mode: fixed | smart | adaptive | fluid }
```

### 2.3 surface（呈现面）

| 字段 | 取值示例 | 来源观察 |
|------|----------|----------|
| `container` | `view` \| `fullscreen_activity` \| `web_dom` \| `native_components` | Activity / Banner View / DOM / MediaView |
| `renderer` | `webview` \| `exo_player` \| `mixed` \| `remote_html` | Unity/LevelPlay Web；Meta Exo；AdMob 远端 |
| `bridge` | `display_message` \| `native_callback` \| `listener_only` | Unity DisplayMessage；LevelPlay NativeCallback；MAX/Meta Listener |
| `measurement` | `omsdk_required` \| `optional` \| `none` | Unity/LevelPlay/AppLovin 打入 OMSDK |

### 2.4 auction（编排面）

| 字段 | 说明 |
|------|------|
| `mode` | `waterfall` \| `bidding` \| `hybrid` \| `direct` |
| `floor_cpm?` | 底价 |
| `networks?` | 允许广告源（聚合时） |
| `bidder_token?` | 是否需要/产生 bidding token（如 Meta） |

### 2.5 creative

| 字段 | 说明 |
|------|------|
| `protocols` | `mraid` \| `vast` \| `native_assets` \| `html` |
| `video?` | `skippable` / `max_sec` / `endcard` |
| `native_assets?` | `icon` \| `image` \| `video` \| `carousel` |
| `cache?` | Meta 式 `none|icon|image|video|all` |
| `click_dest` | `in_app_webview` \| `system_browser` \| `store` |

### 2.6 lifecycle（Bridge 事件契约）

归一事件（跨 SDK 映射目标）：

| 事件 | 含义 |
|------|------|
| `load_ok` / `load_fail` | 加载结果 |
| `show_ok` / `show_fail` | 展示结果 |
| `impression` | 曝光（可与 OMSDK viewable 区分） |
| `click` | 点击 |
| `open_url` | 跳出（浏览器/商店） |
| `reward` | 激励发奖 |
| `close` / `complete` / `skip` | 关闭 / 播完 / 跳过 |
| `revenue` | 展示收益回调（聚合常见） |
| `bid_token` | 竞价令牌就绪 |

```text
lifecycle:
  required: [...]
  optional: [...]
  reward?: { type: currency | item, amount?: number }
```

### 2.7 bindings[]

| 字段 | 说明 |
|------|------|
| `platform` | `admob` \| `adsense` \| `max` \| `levelplay` \| `unity_ads` \| `meta` |
| `ad_unit_id` | 平台广告位 ID |
| `app_id?` | 应用级 ID |
| `placement_name?` | Unity / IronSource 等 name ≠ id 时 |
| `adapter?` | 仅聚合侧适配器标识 |

### 2.8 ops

| 字段 | 说明 |
|------|------|
| `auto_load` | 是否自动预加载 |
| `load_timeout_ms` / `show_timeout_ms` | 超时 |
| `cap` | 会话/日展示上限 |
| `muted_default?` | 默认静音 |
| `orientation?` | `portrait` \| `landscape` \| `sensor` |

## 3. 示例

```json
{
  "id": "home_rv_1",
  "name": "首页激励",
  "scene": "看完发金币",
  "format": "rewarded",
  "surface": {
    "container": "fullscreen_activity",
    "renderer": "webview",
    "bridge": "native_callback",
    "measurement": "omsdk_required"
  },
  "auction": { "mode": "hybrid" },
  "creative": {
    "protocols": ["vast", "mraid"],
    "video": { "skippable": false, "endcard": true },
    "click_dest": "store"
  },
  "lifecycle": {
    "required": ["load_ok", "show_ok", "impression", "reward", "close"],
    "optional": ["click", "revenue"],
    "reward": { "type": "currency" }
  },
  "bindings": [
    { "platform": "levelplay", "ad_unit_id": "xxx", "placement_name": "Home_RV" },
    { "platform": "max", "ad_unit_id": "yyy" },
    { "platform": "meta", "ad_unit_id": "zzz" }
  ],
  "ops": { "auto_load": true, "load_timeout_ms": 30000 }
}
```

Web 位示例：`format=web_slot`，`surface.container=web_dom`，`bindings.platform=adsense`（`ca-pub` + slot）。

## 4. 六平台 Format 对照

| PlacementSpec.format | AdMob（常见） | MAX `MaxAdFormat` | LevelPlay | Unity Ads `AdFormat` | Meta | AdSense |
|----------------------|---------------|-------------------|-----------|----------------------|------|---------|
| `banner` | Banner | BANNER / LEADER | BANNER（+ AdSize） | BANNER | BANNER_* | 展示类广告单元 |
| `mrec` | Medium rectangle | MREC | MEDIUM_RECTANGLE / RECTANGLE | — | RECTANGLE_HEIGHT_250 | — |
| `interstitial` | Interstitial | INTERSTITIAL | INTERSTITIAL | INTERSTITIAL | INTERSTITIAL | — |
| `rewarded` | Rewarded | REWARDED | REWARDED | REWARDED | REWARDED_VIDEO | — |
| `rewarded_interstitial` | Rewarded interstitial | REWARDED_INTERSTITIAL | — | — | experience 可区分 | — |
| `app_open` | App open | APP_OPEN | — | — | — | — |
| `native` | Native | NATIVE | NATIVE_AD | — | NATIVE / NATIVE_BANNER | 相关/信息流类 |
| `web_slot` | — | — | — | — | — | `ca-pub` + slot |

Banner 尺寸补充（聚合侧常见）：

| size.mode / 标签 | LevelPlay / ISBannerSize | MAX | Meta |
|------------------|--------------------------|-----|------|
| 标准横幅 | BANNER | BANNER | BANNER_320_50 / HEIGHT_50 |
| 大横幅 / 90 | LARGE / LEADERBOARD | LEADER | BANNER_HEIGHT_90 |
| 中矩形 | MEDIUM_RECTANGLE | MREC | RECTANGLE_HEIGHT_250 |
| 自适应 / 智能 | SMART 等 | Adaptive 配置 | — |

## 5. 生命周期事件对照

### 5.1 归一事件 → 各侧叫法（示意）

| 归一 | LevelPlay 控制器（摘录） | Unity Ads 舞台 | MAX / 直连 Listener | Meta |
|------|--------------------------|----------------|---------------------|------|
| `load_ok` | `adLoaded` / `LoadSuccess` | Load 完成 | `onAdLoaded` | `onAdLoaded` |
| `load_fail` | `adLoadedError` 等 | Load Error | `onAdLoadFailed` | `onError` |
| `show_ok` | `ShowSuccess` | `DisplayStarted` | `onAdDisplayed` | show 成功路径 |
| `show_fail` | `ShowFailed` | `DisplayError` | `onAdDisplayFailed` | |
| `impression` | `impressionOccurred` | （播放器/OMSDK） | 展示回调 / Impression API | 展示相关 |
| `click` | `adClicked` | （页面内） | click listener | click |
| `open_url` | `openUrl` / StoreKit | `OpenUrl` / `OpenUrlResult` | 系统跳转 | 浏览器/商店 |
| `reward` | `adCredited` | （激励完成） | `MaxReward` / Rewarded listener | `RewardData` |
| `close` | `adClosed` | `DisplayDestroyed` / Finish | `onAdHidden` | close |
| `complete` / `skip` | complete / skip 类 | `ShowStatus` COMPLETED/SKIPPED | 视频 playback listener | |
| `revenue` | ImpressionData 等 | — | `MaxAdRevenueListener` | 多经聚合 |
| `bid_token` | `getToken*` | — | bidding 流 | `BidderTokenProvider` |

### 5.2 Unity `DisplayMessage`（舞台层）

`DisplayReady` · `DisplayStarted` · `DisplayFinishRequest` · `DisplayDestroyed` · `DisplayError` · `FocusChanged` · `VisibilityChanged` · `SetOrientation` · `OpenUrl` · `OpenUrlResult` · `WebViewInstanceRequest` · `WebViewInstanceResponse`

`ShowStatus`：`COMPLETED` | `SKIPPED` | `ERROR`

### 5.3 LevelPlay 控制器漏斗（业务层摘录）

`initAd` → `adLoaded` → `ShowSuccess`/`ShowFailed` → `impressionOccurred` → `adClicked`/`openUrl` → `endCardDisplayed` → `adCredited` → `adClosed`；旁路含 `NativeCallback`、`getOmidData`、banner 可见性与 `NoMoreOffers`。

## 6. 与 SDK 分发/呈现结论的衔接

| 轴 | 对 PlacementSpec 的影响 |
|----|-------------------------|
| 胖包 vs 动态加载 | 一般不进广告位字段；属集成实现细节 |
| 直连网 vs 聚合壳 | 写入 `auction.mode` 与 `bindings[].platform` |
| 呈现套路 A/B/C | 写入 `surface.renderer` / `bridge` |
| OMSDK | `surface.measurement` |

---

## 7. 使用约定

1. 新产品广告位先写 PlacementSpec，再填各控制台 ID 到 `bindings`。  
2. `lifecycle.required` 决定验收：缺 `reward` 的激励位、缺 `impression` 的品牌位视为规格不完整。  
3. 不在 Spec 里复制各 SDK 版本号；版本归各项目依赖锁定 / 官方 Release。  
4. 本文随对照表演进；实现代码或中文站栏目需要时再派生 schema / 表单。
